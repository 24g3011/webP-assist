📝 課題文

フォームにケーキの注文数を入力して送信を押すと，注文内容を2つのテーブルに記録する．

注文時刻テーブル o_time

  • id：フォームのactionで指定したエンドポイントのメソッド内でUUIDを生成し，それをidにする．#4 の2.4節の手法を使うとよい．
  • time：デフォルト制約を付けているのでJavaで現在時刻を取得する必要はない →2.4節

注文テーブル o_qtt

  • 生成したUUIDおよび，フォームから受け取ったケーキID・個数を登録する．

注文を受けるたびに2つのテーブルをSELECT *で表示しておくと何かと捗る．

注文id，時刻，商品名，単価，個数を売上データとして表示する．

  • 客が見る情報と店員が見る情報は別のページに分けるのが普通だが，単一のページで表示してもよいことにする．
  • 3つのテーブルを結合した結果を表示すればよい．

課題文の分解を行う。
「１，フォームにケーキの注文数を入力して送信を押すと、」、「２，注文内容を２つのテーブルに記録する。」、「および１，２の補助説明」、「３，注文id, 時刻, 商品名, 単価, 個数を売上データとして(受け取って)」、「４，表示する」「および３の補助説明」の部分に課題文を分解し、ステップごとに進んでいく。その際、各ステップごとに課題の全文を表示しつつも、そのステップで取り組む部分または関係する部分以外はグレーアウトしておく。

5, ステップアップ

ここでは、実際に課題で要求されているわけではないが、非常に簡単に、より本格的なメニュー表に近づけられる技術を記載する。前の項でcakeshop.htmlに<input type="text" name="count" value="0">を追加した。<input type="text">は「text (=/文字列)を入力できるフィールドを用意する」というような意味の処理である。ここで、目標としている*ステップ1の1-2.htmlページ部分 では、入力される値は「注文数」のことを指すため数字しか受け取る必要が無い。むしろ、注文数の部分に「いち」や漢数字の「一」を入力されると、コントローラー側での処理が非常に難しくなってしまう。そこで、そもそも<input>のtypeにtextではなく、数値を指定して数字だけを入力できるようにした方がよい。

コード比較：

<html xmlns:th="http://www.thymeleaf.org">

<head>
    <meta charset="UTF-8">
    <title>ケーキ通販</title>
</head>

<body>
    <h1>ケーキの注文</h1>

    <div>
        <h2>ケーキの一覧を表示してみる</h2>
        <form action="/order">
            <table border="1">
                <thead>
                    <tr>
                        <th>商品</th>
                        <th>価格</th>
                        <th>注文数</th>
                    </tr>
                </thead>
                <tbody>
                    <tr th:each="cake : ${cakeList}">
                        <td style="display: none;"><input type="hidden" name="id" th:value="${cake.id}"></td>
                        <td th:text="${cake.name}"></td>

-                       <td><input type="text" name="count" value="0"></td>
+                       <td><input type="number" name="count" value="0" min="0"></td>

        </form>
    </div>
</body>

</html>

ここで、<input>の属性としてさらにmin="0"を追加している。これはその名の通り、最小値として0を設定するということ。この<input>フィールドにおいて、入力される数値が0を下回らないようにしている。

2, HTMLからの受け取り(コントローラーの処理-前段階)

現状のCakeShop.javaにはcakeshop.htmlの<form>内のaction="/order"に対応するマッピングが存在しない。そこで、まずはcakeshop.htmlでsubmitボタンが押され、http://localhost:8080/orderが要求された時のRequestMappingを追加する。

詳細解説を開く

Kuchou.javaやDemoApplication3.javaにあるRequestMappingを参考にすると、中身の処理を除いて大きく２種類のRequestMappingが存在することがわかる。１つ目は、

@RequesMapping("/Kuchou")
String haiku(Model model){
	--省略--
	return "haikulist.html";
}

というような、メソッドの引数にModel modelを持ち、returnで"**(htmlファイルの名前)"を指定するものである。２つ目は、

@RequestMapping("/addHaiku")
String addHaiku(@RequestParam("haiku") Haiku haiku){
	--省略--
	return "redirect:/Kuchou";
}

というような、メソッドの引数に@RequestParamを持ち、returnで"redirect:/***(アノテーションの名前)"を指定するものである。詳しい説明や違いが気になる場合は調べたり過去の資料を見るとよい。今回この２つのRequestMappingの違いとして大切なのは、「1つ目のRequestMappingは今のところ、1つのコントローラーにつき1つしか書かない」ということである。
この流れに従うと、現在のCakeShop.javaには既に

@RequestMapping("/")
    String home(Model model) {
        List<Map<String,Object>> cakeList = dao.select7();
        //System.out.println(cakeList); <--確認コード
        model.addAttribute("cakeList", cakeList);
        return "cakeshop"; // ビューの名前
    }

というコードがあり、これは引数にModel modelを持ち、returnで"cakeshop(.html)"を指定しているため、１つ目のRequestMappingがもう使われている。そこで、ここからは２つ目のRequestMappingの書き方を利用していく。

action="order"に対応するため、アノテーションは"/order"にする。また、returnには"redirect:/"を指定するため、型宣言はStringである。@RequestParamの扱いが難しいので、ここではList<Integer> idsとList<Integer> countsとしておく。

コード比較：

詳細解説を開く

cakeshop.htmlの<form>では、現在「モンブラン、アップルパイ、チーズケーキ、ガトーショコラ」の４つの行が表示され、それぞれ注文数がname="count"で設定されている。ここで、submitのボタンを押すとaction="/order"としてコントローラーに"count"の値達が渡ることになるが、コントローラー側から見た時、渡されたデータはMap<String, List<Object>>のような型で{"count", [モンブランのcount, アップルパイのcount, チーズケーキのcount, ガトーショコラのcount]}のようになっている。そのため、@RequestParam("count")でcountの値を受け取ろうとすると、[モンブランのcount,...]が渡されるため、Listとして受け取ることで対処する。

ここで、

@RequestMapping("/order")
    String order(@RequestParam("id") List<Integer> ids, @RequestParam("count") List<Integer> counts) {
+       for(int i = 0; i<counts.size(); i++){
+           System.out.println(counts.get(i));
+       }
        return "redirect:/";
    }

とすると、モンブラン、アップルパイ、チーズケーキ、ガトーショコラの注文数をそれぞれ0,1,0,2などにした時、

0
1
0
2

とターミナルに出力されることから、countsにはこの順でcountの値が格納されていることがわかる。また、idについても同様である。
